## Overview

Beacon .NET 1.0.0 is the first stable release of Beacon's automatic
instrumentation distribution for .NET. It is maintained as a full-source
downstream of OpenTelemetry .NET Automatic Instrumentation and is pinned to the
upstream `v1.17.0` source baseline.

This release provides production-oriented packaging and lifecycle management:
native operating-system packages, portable archives, standalone installers,
one-command execution and removal, cross-platform validation, checksums, an
SPDX SBOM, and GitHub artifact attestations.

## Highlights

- Automatic instrumentation for .NET applications using the OpenTelemetry
  traces, metrics, and logs pipeline.
- Native MSI, DEB, and RPM packages with the unified `beacon-dotnet` command.
- Portable Linux glibc/musl, Windows, macOS, and NuGet archives.
- Shell and PowerShell installers for per-user and non-native installations.
- Complete uninstall support, including cleanup of Windows IIS and registered
  Windows Service instrumentation created by the installation.
- Reproducible release metadata containing the Beacon version, target platform,
  source commit, and pinned upstream provenance.
- SHA-256 checksums, an SPDX SBOM, and GitHub artifact attestations.

## Install a Native Package

Download the package for the host architecture from this Release, then install
it with the operating-system package manager.

### Debian or Ubuntu

```bash
sudo apt install ./beacon-dotnet-1.0.0-linux-amd64.deb
```

Use `beacon-dotnet-1.0.0-linux-arm64.deb` on ARM64.

### RHEL, Rocky Linux, or Fedora

```bash
sudo dnf install ./beacon-dotnet-1.0.0-linux-x86_64.rpm
```

Use `beacon-dotnet-1.0.0-linux-aarch64.rpm` on ARM64.

### Windows

Run the following from an elevated Windows PowerShell session:

```powershell
Start-Process msiexec.exe -Wait -ArgumentList '/i beacon-dotnet-1.0.0-windows-x64.msi'
```

## Install with the Standalone Installer

Standalone installation is recommended for Linux musl, macOS, containers,
per-user environments, and systems where a native package is not appropriate.

### Linux or macOS

The installer uses GitHub CLI to verify the downloaded archive by default.
macOS also requires GNU coreutils.

```bash
curl -sSfL \
  https://github.com/beacon-observability/beacon-dotnet/releases/download/v1.0.0/otel-dotnet-auto-install.sh \
  -o otel-dotnet-auto-install.sh

VERSION=v1.0.0 sh ./otel-dotnet-auto-install.sh
. "$HOME/.otel-dotnet-auto/instrument.sh"
```

### Windows PowerShell

Run Windows PowerShell 5.1 as administrator:

```powershell
Invoke-WebRequest `
  https://github.com/beacon-observability/beacon-dotnet/releases/download/v1.0.0/OpenTelemetry.DotNet.Auto.psm1 `
  -OutFile OpenTelemetry.DotNet.Auto.psm1

Import-Module ./OpenTelemetry.DotNet.Auto.psm1
Install-OpenTelemetryCore
Register-OpenTelemetryForCurrentSession -OTelServiceName "my-service"
```

The standalone installers require GitHub CLI for default release and
attestation verification. Explicit verification opt-out options exist for
controlled offline environments, but skipping verification is not recommended.

## Configure and Run an Application

At minimum, set a service name and configure the OTLP destination used by the
environment. For example:

```bash
export OTEL_SERVICE_NAME=my-service
export OTEL_EXPORTER_OTLP_ENDPOINT=http://collector.example:4318
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf

beacon-dotnet run dotnet MyApplication.dll
```

For a standalone Shell installation, source `instrument.sh` and run the
application directly. For PowerShell installations, call
`Register-OpenTelemetryForCurrentSession` before starting the application.

See the [configuration documentation](https://github.com/beacon-observability/beacon-dotnet/blob/v1.0.0/docs/config.md)
for exporters, resource attributes, instrumentation controls, and advanced
options.

## Management and Uninstallation

Native package installations expose the same management interface on every
supported operating system:

```text
beacon-dotnet status
beacon-dotnet version
beacon-dotnet run <application-command> [arguments]
beacon-dotnet uninstall
```

Standalone installations include dedicated uninstallers:

```bash
sh "$HOME/.otel-dotnet-auto/uninstall.sh"
```

```powershell
& "$env:ProgramFiles\OpenTelemetry .NET AutoInstrumentation\uninstall.ps1"
```

Uninstallation is idempotent. The Unix uninstaller refuses to remove a target
that does not contain Beacon metadata. The Windows uninstaller cleans the
current session and detects IIS and Windows Service registrations that refer to
the installed profiler before removing files.

## Supply-Chain Verification

The 15 downloadable payloads are recorded in `checksums.txt`. After downloading
the assets into one directory, verify them with:

```bash
sha256sum --check checksums.txt
```

Each release asset also has a GitHub artifact attestation produced by the
repository's release workflow. Verify an asset with GitHub CLI:

```bash
gh attestation verify ./<asset> \
  --repo beacon-observability/beacon-dotnet \
  --signer-workflow beacon-observability/beacon-dotnet/.github/workflows/beacon-release.yml \
  --source-ref refs/tags/v1.0.0
```

## Known Limitations

- MSI, DEB, and RPM files are not yet Authenticode-signed or distributed
  through signed package repositories. Verify GitHub artifact attestations
  before installation.
- End-to-end ingestion into DataKit is not part of the verified release scope.
- Beacon-specific runtime enhancements are not included in this release; the
  runtime behavior is inherited from the pinned OpenTelemetry upstream.
- The standalone Windows module supports Windows PowerShell 5.1.
- macOS Shell installation requires GNU coreutils.

For detailed usage, IIS and Windows Service registration, containers,
troubleshooting, and advanced configuration, see the
[documentation](https://github.com/beacon-observability/beacon-dotnet/tree/v1.0.0/docs).
